## Motivation
A pre-proving READINESS audit (same three agents) found Trezarr's central moat claim — "the same directed pronoun pair for every relationship, episode 1 → finale" — was **not delivered** cross-episode in the automatic (unlocked) case. Names + locked terms carried forward; directed pronoun PAIRS did not. Two VERIFIED drift vectors (production never auto-locks pairs; locks come only from the UI):
- **Vector 1 (producer):** Pass-1 inference overwrote an established unlocked pair's terms with no `relationship_event`.
- **Vector 2 (consumer):** reconcile's safe-default ladder dropped an established `(anh/em)` to stranger `(tôi/bạn)` when an episode lacked a clean witness — *asserted by the project's own tests*. This reproduced MT failure mode #6 (cross-episode drift) — the exact thing the product exists to prevent.

The linguist established the moat-correct **precedence ladder**: `human lock > genuine evolution (this-episode relationship_event) > carried Bible pair > current-episode safe-default (truly-new dyad only)`.

## The fix
- **reconcile.py** (no-survivors else-branch ~526-540): before safe-defaulting, carry the established unlocked pair forward into `resolved_map` (only when a prior entry with non-None terms exists). Lock + transition branches `continue` earlier, so carry-forward structurally cannot beat a lock or a logged evolution; a truly-new dyad still safe-defaults. Carries into `resolved_map` ONLY — no DB write, no `valid_from_episode` bump.
- **analyze.py** (Pass-1 Step 4 ~760-788): create-or-affirm. For an EXISTING pair, pass `self_term=None / address_term=None / valid_from_episode=None` → store.py's `if new_val is None: continue` (704-706) preserves the established terms AND the original marker. A brand-new pair still gets its inferred terms + `episode_key`. An established pair's terms now change only via a `relationship_event` or a human lock.
- **engine.py** Pass-3 (~1785): no logic change — `resolved_map.get((spk_id,addr_id))` already keys the hint, so a carried pair reaches the subtitle (Vector 2b confirmed closed).
- **Tests:** 2 contract tests re-pointed (knowing, verifier-confirmed correct contract change) + 7 regression tests (carry / truly-new-default / evolution / lock / reciprocal coherence / create-or-affirm / valid_from_episode-no-op).

## Findings
### [LOW] affirm bumped `valid_from_episode` every episode — **FIXED** (`f82b33b`)
Both specialists flagged it; the create-or-affirm path passed `valid_from_episode=episode_key` even on a terms-unchanged affirm, bumping the D-53 marker + growing the audit trail unboundedly across a series (no pronoun/viewer effect). Fixed symmetrically: `valid_from_episode=None if pair_already_exists else episode_key`. RED/GREEN test added. Affirm is now a true no-op on an existing row.
