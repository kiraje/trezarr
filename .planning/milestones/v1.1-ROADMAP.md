## Overview

v1.1 (UI v2: shadcn dashboard) continues phase numbering at 11. The core translation engine is
unchanged; this is a UI/UX and library-browsing milestone. The build order is dependency-forced:
shadcn foundation first (gates everything), then app shell + route restructure (wraps all pages),
then backend episodes enrichment (parallel-eligible with the shell; must land before the Series
detail page), then new library pages (headline deliverables), then reskin-in-place of existing
pages (BibleEditor last — highest regression risk), then Docker rebuild and live smoke test as
the release gate.

## Milestone Summary

**Key Decisions** (see PROJECT.md / STATE.md Key Decisions):

- Phase 11 pins `shadcn@2.10.0 init` (not @latest) — shadcn@latest (4.x) emits Tailwind v4 config that breaks the existing Tailwind v3.4 PostCSS pipeline; the `add` command for components can use @latest safely.
- NAV-03 (count/LIVE badges) assigned to Phase 14 — badge data requires API-02 `translated_count`/`total_count` from Phase 13; Phase 12 ships placeholder/zero badges.
- Phase 13 (backend enrichment) is parallel-eligible with Phase 12 (shell); Phase 14 (SeriesDetail) blocks on both Phase 12 (layout route / Outlet) and Phase 13 (stable API contract).
- BibleEditor reskin is Phase 15 (last page) — 88KB, 5 previously-fixed critical locking bugs; reskin-in-place only (token substitution, no logic changes); test suite must stay green.
- Bridge-period dual-token strategy — legacy hex tokens kept in tailwind.config.js until all pages are reskinned; removed atomically in Phase 15 once `grep "bg-[#"` returns zero results.

**Audit verdict (2026-06-04):** PASSED — 17/17 requirements satisfied (3-source cross-reference), 6/6 phases complete, cross-phase integration CLEAN (27/27 backend routes have consumers), E2E flows confirmed live by the operator smoke test (8/8) against the real *arr stack on :6868. No blockers. See `v1.1-MILESTONE-AUDIT.md`.

**Issues Resolved During Milestone:**

- Phase 15 review (fixed before close): reciprocal double-toast, ConnectionTestButton resetKey, BibleEditor Fragment keys, FieldHistoryPanel close button.
- Phase 12 sidebar a11y advisory (WR-02): added `aria-keyshortcuts` to the Sidebar.

**Technical Debt Incurred (non-blocking — carry forward):**

- **W1** (NAV-03/LIB-06): LIVE sidebar badge false-positives for a DISABLED *arr service — `getSeriesLiveBadge`/`getMoviesLiveBadge` infer LIVE from `len>0 || no error`, and a disabled service yields `[]`+no-error → green LIVE. API exposes no positive enabled/connected flag. Cosmetic; only bites when a service is turned off (operator deployment has them enabled). `frontend/src/contexts/LibraryContext.tsx:72-83`. Follow-up ticket.
- **W2** (LIB-03/API-02): `series_title` modeled `string?` (optional) in `client.ts:546` but backend always emits the key with possible `null` value (`library.py:407`). Runtime-safe via `data?.series_title ?? 'Series #id'`. Type-contract drift only.
- **W3** (LIB-04/API-02): Bazarr episode-inventory posts `seriesid[]` with no runtime fallback to plain `seriesid` (`library.py:315-333`, TODO(phase-16)). Confirmed working by the live smoke test (badges populated) but remains an assumption, not a code-guaranteed contract. Fail-soft. Follow-up ticket.
