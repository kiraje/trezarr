# Requirements (Archived): Trezarr v1.0 — MVP

**Defined:** 2026-05-31
**Shipped:** 2026-06-03
**Core Value:** Vietnamese subtitles that stay consistent and relationally correct (right pronoun pair, stable names/terms) across an entire series — produced automatically.

> **Archive note:** This is the frozen v1.0 requirements set. All 40 requirements are mapped
> to phases 1–10 and marked Complete. Five Series-Bible requirements (BIBLE-01/02/04/05/06)
> ship as **structurally complete** — the persistence, schema, lock-precedence, and
> carry-forward are implemented and unit-verified — but their checkbox was left unchecked in
> the live source because end-to-end **behavioral** confirmation against a frontier model was
> never run (`ds/deepseek-v4-pro` insufficient). The translation core-value verification is the
> milestone's top carry-forward item. See `v1.0-ROADMAP.md` → Milestone Summary → Issues
> Deferred and `v1.0-TRANSLATION-VERIFICATION-FINDINGS.md`.

## v1.0 Requirements (40 total — all mapped, all shipped)

### Integration

- [x] **INTG-01**: Connect to Sonarr and Radarr via their REST APIs (API-key auth) to discover the media library, episode/movie identity, file paths, and metadata — Phase 3
- [x] **INTG-02**: Connect to Bazarr via its API to read which source-language subtitles already exist (so it never re-downloads subs) — Phase 10
- [x] **INTG-03**: User can configure container↔host path mapping so Trezarr resolves the same media files the *arr stack sees — Phase 3
- [x] **INTG-04**: Read source subtitle files and write Vietnamese sidecar files on the shared filesystem with correct permissions (PUID/PGID) — Phase 3

### Discovery & Automation

- [x] **AUTO-01**: Automatically detect media that has a source subtitle but no good Vietnamese subtitle and queue it — Phase 3
- [x] **AUTO-02**: Monitor for newly added media / new source subtitles on an ongoing basis (polling, with webhook trigger support) — Phase 7
- [x] **AUTO-03**: Idempotent — tracks per-item state (incl. source-sub hash), skips items already up to date, never causing re-translation storms — Phase 3
- [x] **AUTO-04**: Excludes its own output from re-triggering the watcher (no self-reprocessing loop) — Phase 3 (generalized for `.vi.<ext>` in Phase 9)
- [x] **AUTO-05**: Processing resumes safely after a crash or restart without losing or duplicating work — Phase 7

### Subtitle Formats

- [x] **FMT-01**: Parse and write SRT, preserving indices, timecodes, and line segmentation exactly (text only, never timestamps) — Phase 1
- [x] **FMT-02**: Parse and write ASS/SSA, translating only dialogue text and leaving override tags, drawing commands, `\N` breaks, and headers byte-identical — Phase 9
- [x] **FMT-03**: Preserve karaoke (`\k`) lines without corruption (verbatim if remapping is unsafe) — Phase 9
- [x] **FMT-04**: Parse and write VTT, round-tripping cue settings/positioning — Phase 9 *(positioned-sign rendering visual UAT 09-06 deferred — see roadmap archive)*
- [x] **FMT-05**: Correct sidecar naming (`Show.S01E01.vi.srt`), atomic write (temp+rename), valid UTF-8 — Phase 2

### Translation Engine

- [x] **ENG-01**: Configure a user-provided OpenAI-SDK-compatible endpoint (base URL, model, API key) — Phase 1
- [x] **ENG-02**: Batch/chunk long files within token limits without splitting a sentence or scene across boundaries — Phase 2
- [x] **ENG-03**: Translate each batch with a surrounding-line context window — Phase 2
- [x] **ENG-04**: Two-pass pipeline — Pass 1 analyzes the full file + metadata to build/update the Bible before Pass 2 translates — Phase 5
- [x] **ENG-05**: LLM self-review pass over translated output (Bible adherence), correcting violations before finalizing — Phase 6
- [x] **ENG-06**: Hard pre-write validation gate (cue-count match, no untranslated lines, timing preservation, format integrity); failing files quarantined — Phase 2
- [x] **ENG-07**: A failed/rejected translation can be retried/re-run idempotently, reusing existing Bible state — Phase 2

### Series Bible (Consistency Engine)

> Implemented + unit-verified; behavioral end-to-end confirmation against a frontier model is the deferred core-value item.

- [x] **BIBLE-01**: Persistent per-series Series Bible loaded as context every episode and updated after each — Phase 4 *(structural; behavioral verification deferred)*
- [x] **BIBLE-02**: Records Characters (name in original Latin form, gender, rough age, role) — Phase 4 *(structural; behavioral verification deferred)*
- [x] **BIBLE-03**: Records a directed Address Map — per ordered pair, self-term + address-term, supporting asymmetric pairs — Phase 5
- [x] **BIBLE-04**: Records a Term Dictionary (proper nouns/titles/places/jargon → fixed Vietnamese renderings, incl. name-romanization policy) — Phase 4 *(structural; behavioral verification deferred)*
- [x] **BIBLE-05**: Records a Register/tone per series grounded in media metadata — Phase 4/5 *(structural; behavioral verification deferred)*
- [x] **BIBLE-06**: Carried forward across episodes so a character is addressed consistently from S01E01 to the finale — Phase 4 *(structural; behavioral verification deferred)*
- [x] **BIBLE-07**: Tracks relationship evolution across episodes with episode markers so pronoun choices change correctly over the series — Phase 6
- [x] **BIBLE-08**: User can view and edit the Series Bible; edits are lockable and survive re-analysis — Phase 8
- [x] **BIBLE-09**: Locked corrections propagate forward to all subsequent episode translations (the human override valve) — Phase 8

### Pronoun Attribution

- [x] **PRON-01**: Infers speaker and addressee per line from dialogue content, turn-taking, and vocatives — Phase 5
- [x] **PRON-02**: Applies the correct Vietnamese pronoun pair from the Address Map based on the inferred speaker→addressee relationship — Phase 5
- [x] **PRON-03**: Low-confidence attribution falls back to a safe register rather than risk a wrong intimate pronoun — Phase 5

### Source Selection

- [x] **SRC-01**: Source-language-agnostic — can translate from any available source-language subtitle to Vietnamese — Phase 10
- [x] **SRC-02**: With multiple sources, selects the source language whose honorific/relational system best preserves what Vietnamese needs (prefer zh/ko/ja/th for East-Asian content over English), falling back to whatever is available — Phase 10

### Service & Web UI

- [x] **SVC-01**: Single Dockerized, long-running self-hosted service deployable alongside the *arr stack (`/config` volume) — Phase 7
- [x] **SVC-02**: Web UI to configure connections (Sonarr/Radarr/Bazarr, LLM endpoint, paths) and global settings — Phase 7
- [x] **SVC-03**: Web UI shows Queue (in-flight), History (completed/failed with reason), and per-job logs — Phase 7
- [x] **SVC-04**: Retry or re-run a failed/rejected item from the UI — Phase 7
- [x] **SVC-05**: Per-series overrides (source-language preference, register, model) — Phase 10

## Out of Scope (v1.0)

| Feature | Reason |
|---------|--------|
| Target languages other than Vietnamese | Vietnamese relational consistency is the hard problem and the moat; multi-target dilutes the engine |
| Re-downloading / acquiring source subtitles | Bazarr already does this seamlessly; duplicating it competes with the tool we integrate with |
| Bundling/hosting a local LLM model | User brings their own OpenAI-compatible endpoint; hosting models is an ops burden |
| Per-line human review/correction workflow UI | Contradicts the fully-automated mission; the editable Series Bible is the only human touchpoint |
| Cost/token budgeting dashboards | User runs their own endpoint; per-call cost is not a concern |
| Burning subtitles into video / re-muxing | Destroys the sidecar model media servers rely on; heavy and risky |
| Real-time/streaming translation | The consistency engine needs the whole file up front; accuracy over latency |
| Auto-syncing/re-timing subtitles | That's Bazarr/sub-sync's job; mixing it in risks breaking preserved timing |
| Generating subs from audio (ASR/Whisper) | Different problem (speech→text); Trezarr translates existing subs |
