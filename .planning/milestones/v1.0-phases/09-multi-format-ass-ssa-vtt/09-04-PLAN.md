    Create trezarr/subtitles/vtt.py following srt.py's structure. Module docstring should describe the byte-identity strategy: "VTT envelope is a block list. WEBVTT header + opaque blocks (NOTE/STYLE/REGION/malformed) are VttOpaqueBlock entries. Translatable cues are VttCueBlock entries (verbatim timing_line + settings + verbatim identifier). Only the cue payload text changes on translate."

    Imports: same pattern as ass.py (from __future__ import annotations, re, warnings, dataclasses, Path, detect_encoding, SubDoc, SubLine).

    Envelope dataclasses (RESEARCH §4.1 / PATTERNS.md §"vtt.py"):
    VttOpaqueBlock(raw: str, trailing_sep: str)
    VttCueBlock(identifier_line: str | None, timing_line: str, line_ending: str, sub_index: int, trailing_sep: str)
    VttDoc(blocks: list, encoding: str, line_ending: str)

    Internal regex: _VTT_TIMING_RE = re.compile(r'-->') — used to detect which line is the timing line.

    read_vtt(path) algorithm (RESEARCH §4.2):
    1. read_bytes → detect_encoding → decode with errors="replace"
    2. Detect line ending (same srt.py pattern: "\r\n" if "\r\n" in text else "\n")
    3. Split on blank lines using the same _SEP_RE from srt.py: re.compile(r"((?:\r?\n)(?:[ \t]*\r?\n)+)"). tokens = _SEP_RE.split(text). block_texts = tokens[0::2], separators = tokens[1::2]. Ensure separators list is padded to len(block_texts) with "" if needed.
    4. First block_text is always the WEBVTT header block → VttOpaqueBlock(raw=block_texts[0], trailing_sep=separators[0] if separators else "").
    5. For each subsequent (block_text, trailing_sep) pair: call _parse_vtt_block(block_text, trailing_sep) → VttOpaqueBlock or VttCueBlock.
    6. _parse_vtt_block logic (PATTERNS.md §"_parse_vtt_block"):
       - If empty: VttOpaqueBlock
       - If first line starts with NOTE, STYLE, REGION: VttOpaqueBlock
       - If first line contains "-->": timing_line = first_line, identifier_line = None, payload = remaining lines joined with le
       - If second line contains "-->": identifier_line = first_line, timing_line = second_line, payload = remaining
       - Otherwise: UserWarning malformed + VttOpaqueBlock (D-10)
       - For a valid cue: extract start_tc from timing_line (everything before " --> "), end_tc from just after " --> " up to the first space or end-of-line. The rest of the timing_line (after end_tc) = the settings string. Store the whole timing_line verbatim in VttCueBlock.timing_line. payload = multi-line cue text (join remaining lines). SubLine(index="", start_tc=start_tc.strip(), end_tc=end_tc.strip(), text=payload)
    7. Construct VttDoc(blocks=blocks, encoding=encoding, line_ending=le)
    8. Return SubDoc(lines=sub_lines, encoding=encoding, line_ending=le, separators=[], leading="", trailer="", envelope=vtt_doc)

    write_vtt(doc, path) algorithm (RESEARCH §4.1 write-back):
    Iterate vtt_doc.blocks:
    - VttOpaqueBlock: emit raw + trailing_sep
    - VttCueBlock: emit (identifier_line + le if identifier_line else "") + timing_line + le + doc.lines[block.sub_index].text + trailing_sep (note: .text may contain the translated multi-line payload; if raw is not None, emit raw instead of text)

    result = "".join(parts); Path(path).write_bytes(result.encode(vtt_doc.encoding))

    Key constraints:
    - SubLine.index = "" for all VTT cues (VTT cue identifiers are stored in VttCueBlock.identifier_line, not in SubLine — the identifier is structural, not an index)
    - Cue settings are part of timing_line verbatim — never parsed or modified
    - Multi-line cue payloads: SubLine.text stores the full payload with internal line endings preserved (same as SRT multi-line; Python join with le for the lines after the timing line)
    - CRLF: use the detected le for emitted line endings in VttCueBlock write-back; VttOpaqueBlock.raw is verbatim so its CRLFs are preserved
    - VTT encoding is UTF-8 by spec; detect_encoding handles the optional BOM

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VTT file bytes → read_vtt | Untrusted bytes from disk subtitle files |
| Cue payload text → SubLine.text | May contain inline VTT tags (<v>, <c>, timestamps) — sentinel.py handles protection downstream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04-A | Denial of Service | _VTT_TIMING_RE: `-->` | accept | Simple fixed-string search, no quantifiers, no backtracking. Zero ReDoS exposure. |
| T-09-04-B | Denial of Service | _SEP_RE blank-line split | accept | Reused from srt.py which is already in production. Same per-file application context. |
| T-09-04-C | Tampering | VTT STYLE block CSS | accept | CSS content in STYLE blocks is emitted verbatim by VttOpaqueBlock. Trezarr never parses or executes CSS. Media player renderer handles CSS; not a Trezarr concern. |
| T-09-04-D | Tampering | VTT cue identifier as label | accept | Cue identifiers are structural labels stored in VttCueBlock.identifier_line and emitted verbatim. Never executed or used as a path. |
| T-09-04-E | Tampering | Path traversal via sidecar | accept | Same as T-09-03-F — vtt.py is a pure codec; path-traversal guard is upstream in write_vi_sidecar. |
</threat_model>
