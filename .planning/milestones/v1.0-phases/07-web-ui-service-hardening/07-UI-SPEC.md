# Phase 7 — UI Design Contract

> Visual and interaction contract for Phase 7: Web UI & Service Hardening.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `p-1` / `gap-1` | Icon-to-label gaps, badge internal padding |
| sm | 8px | `p-2` / `gap-2` | Compact row padding, inline element gaps |
| md | 16px | `p-4` / `gap-4` | Default cell padding, form field spacing |
| lg | 24px | `p-6` / `gap-6` | Card / section padding |
| xl | 32px | `p-8` / `gap-8` | Content area horizontal padding |
| 2xl | 48px | `py-12` | Major section breaks (empty states) |
| 3xl | 64px | `py-16` | Page-level top/bottom padding |

Exceptions:
- Sidebar nav item touch target: minimum 40px height (`min-h-10`) for usable click area on a narrow window.
- Table row height: 40px (`h-10`) — compact density like Bazarr, not spacious card rows.
- Status badge height: 20px (`h-5`) — tight inline badge so it does not blow out row height.
- Connection test result inline: 28px (`h-7`) so the ok/error chip sits flush with the Test button.

| Tertiary (table stripe) | `#1e2130` (`--bg-stripe`) | `bg-[#1e2130]` | Alternating table rows — subtle, not distracting |
| Border | `#2d3148` (`--border`) | `border-[#2d3148]` | All borders: table, card, input, sidebar |

**Accent (`#3b82f6` — blue) reserved exclusively for:**
1. Active nav item indicator (left border or background highlight)
2. Primary action buttons ("Test Connection", "Save Settings", "Retry")

Accent is NOT used for: status badges (they have their own semantic palette below), table hover, input focus rings (use `outline: 2px solid #3b82f6; outline-offset: 2px` for focus — full opacity, no transparency), general decorative purposes.

The following components must be built as reusable primitives. Each is hand-rolled with Tailwind; no shadcn or external component library is used.

```
├──────────┬──────────────────────────────────────┤

│          │                                      │
│ Settings │                                      │
│ Queue    │                                      │
│ History  │                                      │
│          │                                      │
│ (Phase 8 │                                      │
│  Bible   │                                      │
│  slot —  │                                      │
│  visible │                                      │
│  but dim │                                      │
│  "soon") │                                      │
└──────────┴──────────────────────────────────────┘
```

- **TopBar:** 48px height, secondary background, Trezarr wordmark in text-primary at 16px semibold, service status dot (green=running, gray=stopped, red=error) on the right edge.
- **Sidebar:** 192px (w-48) fixed width, secondary background, left border at domain color. Nav items: 40px min-height, 16px horizontal padding, 14px regular text. Active item: left 2px blue accent border + slightly lighter background (`#1e2130`). "Bible" nav item present but visually muted (`text-muted`, non-clickable or routes to a "Phase 8" placeholder) to signal extensibility.
- **Content area:** `flex-1`, base background, xl (32px) horizontal padding, lg (24px) vertical padding.

### StatusBadge

Props: `status: "queued" | "running" | "done" | "failed" | "quarantined"`

Renders: `<span>` with 4px colored dot + status text label. Height 20px, 6px horizontal padding, 4px gap between dot and text, 12px regular text. Background and text from semantic status palette above.

Never render a badge that is color-only. Screen readers read the text label.

### MaskedSecretInput

A text input used for API keys and other SecretStr fields.

- Displays as `type="password"` by default (browser masks with bullets).
- When the field has an existing value (server returns `is_set: true`), show placeholder `"••••••••"` and a "set" chip (12px muted text) to the right.
- Input value is only sent to the backend when the user explicitly types a new value. If the user clears and re-types the same content, it is still treated as a new value (safe — idempotent on backend).
- A small eye-toggle button (lucide `Eye` / `EyeOff`) reveals the typed (not stored) value. The stored secret is never revealed.
- If the field is env-locked: render as a disabled `<input type="text">` showing `"set via environment variable"` in muted italic text. Add a tooltip (or adjacent label): "This value is set by the TREZARR_* environment variable and cannot be overridden from the UI."

### ConnectionTestButton + ResultChip

- Button labeled "Test Connection" (14px, accent background, white text, 8px vertical padding, 16px horizontal).
- On click: button shows spinner, becomes disabled.
- On result: a ResultChip appears inline to the right of the button (28px height, 8px horizontal padding, 12px regular text). Uses connection test palette above (ok = green chip with check icon; error = red chip with X icon + truncated error message on hover/tooltip).
- Result chip clears when the connection form fields are edited again.

### JobTable (Queue and History views share one component, parameterized)

Columns vary by view — see Copywriting Contract for exact column labels. All tables:

- Full-width, no horizontal scroll on desktop (columns constrained to fit).
- Column headers: 12px regular, muted color, uppercase, 40px row height.
- Body rows: 40px height, 14px regular, alternating stripe (`bg-stripe` on odd rows).
- Row hover: `bg-[#22263a]` (subtle highlight, no heavy color shift).
- No row selection (not needed for v1).
- Truncate long file paths with CSS `truncate` and show full path on hover via `title` attribute.
- StatusBadge in the Status column.
- Actions column (right-aligned): icon buttons only (Retry = lucide `RefreshCw`, Logs = lucide `FileText`). 32px × 32px touch target, muted color, blue on hover.
- Empty state: full-width centered empty state block (see Copywriting Contract).

### LogViewer

Used in the per-job Logs view.

- Monochrome dark terminal aesthetic: base background, 13px monospace text, `#4ade80` for INFO, `#f87171` for ERROR, `#fb923c` for WARNING, `#94a3b8` for DEBUG.
- Lines are `<div>` elements, not a `<pre>` block, to allow line-level coloring.
- Log level prefix on each line: `[INFO]`, `[ERROR]`, `[WARN]`, `[DEBUG]` — 5-char fixed width with space padding.
- Scrollable area with `overflow-y: auto`, max-height `calc(100vh - 200px)`.
- No word-wrap: log lines are not wrapped (overflow hidden with horizontal scroll).
- A "scroll to bottom" button (lucide `ChevronsDown`) appears when the user has scrolled up, fixed to the bottom-right of the log area.
- Timestamp per line: `HH:MM:SS` prefix in muted color before the level prefix.

### RetryButton + ConfirmationInline

Used on failed/quarantined items in History.

- Primary: lucide `RefreshCw` icon + "Retry" label, 14px, accent color text on transparent background (ghost button style).
- On click: inline confirmation replaces the button: `"Re-queue this item?" [Re-queue] [Cancel]` — no modal dialog. Re-queue button is accent; Cancel is ghost. This prevents accidental retries without the cost of a modal.
- On confirm: button shows spinner. Row status badge updates to "queued" when the API responds. If the API returns an error, show an error toast (see below).

### Toast / Notification

Minimal: a fixed-position strip at the bottom-right of the viewport, 280px wide. Two variants:
- Success: green left-border (`#22c55e`), secondary background, 14px text.
- Error: red left-border (`#ef4444`), secondary background, 14px text.

Auto-dismisses after 4 seconds. No animation (functional-first). Single toast at a time; new toast replaces the previous one.

## Surface Specifications

### Settings View

Layout: vertical stack of connection sections. Each section is a card (`bg-surface`, `border-border`, 8px border-radius, 24px padding).

Primary visual anchor: the first connection section (LLM Endpoint) — first in reading order, most-used configuration surface.

Sections (in order):
1. LLM Endpoint (base URL, model, API key)
2. Sonarr (host, port, API key) + Test Connection button
3. Radarr (host, port, API key) + Test Connection button
4. Bazarr (host, port, API key, enabled toggle) + Test Connection button
5. Path Mappings (host path → container path pairs)
6. Service Settings (poll interval, max concurrent series, webhooks toggle)

Each section has a 16px semibold heading at the top.

Field layout: two-column grid on wide viewports (`grid-cols-2 gap-4`), single column below 768px. Labels above inputs (not inline). Each label is 12px regular muted. Each input is 36px height, full-width, secondary background, border-border border, 8px horizontal padding, 14px regular text. Focus ring: `outline: 2px solid #3b82f6; outline-offset: 2px`.

Save button: "Save Settings" — full-width within each section card, accent background, white text, 36px height. Positioned at the bottom of each section. Disabled when no unsaved changes in that section.

Env-locked fields: rendered as disabled inputs with `"set via environment variable"` placeholder in muted italic. A small `lock` icon (lucide `Lock`, 12px, muted) appears inline with the label.

Restart-required fields: after saving, if any changed field requires a restart, show an inline banner inside the section card: "Some changes require a service restart to take effect." (amber text, `#fbbf24`, no background color — just text with an info icon).

## Interaction & State Contracts

### Polling behavior

- Queue view: polls `GET /api/queue` every 10 seconds.
- History view: polls `GET /api/jobs` every 30 seconds.
- No SSE/WebSocket (D-73: deferred nice-to-have).
- Poll uses `fetch` with a timeout of 5 seconds. On network error, show the API unreachable error banner (amber strip at top of content area, not a blocking modal).
- Status is not shown as loading on re-polls — the table updates in-place. No spinner between polls.

### Form state

- Unsaved changes: track dirty state per section. "Save Settings" button is disabled when no changes in that section.
- After save: button returns to "Save Settings" label; dirty state clears.
- Validation: required fields show a 12px red error message below the input on blur if empty. No client-side validation beyond "required" — backend validates the rest.

### API-unreachable state

- If `GET /api/queue` or `GET /api/jobs` returns a network error or 5xx: show the API unreachable banner (amber background `#451a03`, amber text `#fbbf24`, 14px, `"Cannot reach the Trezarr service. Check that the server is running."`). Banner dismisses automatically when the next poll succeeds.
- Settings POST failure: show error toast (see Toast component).

### Navigation

- React Router (or equivalent simple client-side routing). Routes: `/settings`, `/queue`, `/history`, `/jobs/:id/logs`.
- Default route (`/`): redirect to `/queue`.
- The sidebar "Bible" link is present but routes to a placeholder page with body text: "Series Bible editing will be available in a future release."

## Accessibility Contract

- All interactive elements (buttons, inputs, nav items) have visible focus rings (`outline: 2px solid #3b82f6; outline-offset: 2px`).
- Status badges carry both a color indicator AND text label. Screen readers read the text.
- The TopBar service status dot carries an `aria-label` (e.g. `aria-label="Service status: running"`).
- Table columns have `<th scope="col">` headers.
- Icon-only buttons (Logs icon, Retry icon) carry `aria-label` attributes.
- Keyboard: Tab navigates all interactive elements; Enter activates buttons.
- No ARIA role heroics needed — use semantic HTML (`<nav>`, `<main>`, `<table>`, `<button>`, `<label for>`).

## Responsiveness

Desktop-first. Target: full usability at 1280px wide. Minimum window tested: 900px wide.

- Below 768px: sidebar collapses to a horizontal top nav strip (icon-only, with labels on hover).
- Table columns on narrow viewport: hide the "File" column below 900px; truncate "Series" aggressively. All other columns remain visible.
- Form fields: single column below 768px (as noted in Settings specification above).

## Implementation Notes for Executor

1. **No design system — build exactly what is specified.** Do not reach for shadcn or Radix. Hand-roll the components listed in the Component Inventory using Tailwind utility classes.

2. **Tailwind config:** Use the hex values above verbatim. Define them in `tailwind.config.js` under `theme.extend.colors` with the CSS var names as keys for IDE discoverability. Do not use the default Tailwind color palette names (blue-500 etc.) in component code — use the semantic names from this spec (`text-accent`, `bg-surface`, etc.).

3. **No CSS animations.** `transition-colors duration-150` on hover states is acceptable (functional feedback). No enter/exit animations, no loading skeletons, no framer-motion.

4. **Tailwind CSS v3** (not v4 — v4 is alpha). Pin `"tailwindcss": "^3.4"` in package.json.

5. **Polling implementation:** Use `setInterval` inside a `useEffect` with cleanup. Do not use react-query or SWR for v1 — the polling surface is small (two endpoints) and a custom hook is cheaper than a library dependency.

6. **Table as `<table>` element.** Do not use CSS grid or flexbox to simulate tables. `<table>` + `<thead>` + `<tbody>` + `<tr>` + `<th>` + `<td>` is the correct semantic element and is easier to make accessible.

7. **Route structure in Vite:** Configure `vite.config.ts` with `build.outDir: "../trezarr/web/static"` (or `"../frontend/dist"` copied at Docker build time). The FastAPI `StaticFiles(html=True)` mount handles SPA routing fallback.

8. **API client:** One file `frontend/src/api/client.ts` with typed fetch wrappers for each endpoint. No axios — native `fetch` is sufficient and ships with every browser React 19 targets.
