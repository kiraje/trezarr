# Phase 12 — UI Design Contract

> Visual and interaction contract for Phase 12: App Shell + Route Restructure.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> SCOPE FRAMING: Phase 12 builds NO new page *content*. It replaces the layout
> chrome — drops the 48px TopBar, introduces the shadcn `SidebarProvider` +
> `AppSidebar` + `<Outlet/>` shell, restructures the route table (`/library`
> splits into `/series` + `/movies` + `/series/:seriesId`; `/` → `/series`),
> and renders heading-only stub pages for Series/SeriesDetail/Movies. All design
> TOKENS (purple palette, spacing, typography) are INHERITED unchanged from the
> Phase-11 contract. This spec adds only the SHELL COMPOSITION + COLLAPSED-STATE
> behavior + BRAND header + FOOTER status row + ACTIVE-ACCENT interaction on top
> of that locked palette.
>
> Requirements covered: NAV-01 (sidebar shell + brand + active accent bar),
> NAV-02 (six-item nav; `/library` split; `/` → `/series`). NAV-03 (count + LIVE
> badges) is Phase 14 — OUT of scope.

## Typography

Inherited verbatim from Phase 11. **Contract: exactly 2 weights (400 / 600).**
Phase 12 introduces only three short text strings (brand pill, nav labels, stub
headings); all map onto the existing roles below.

| Role | Size | Weight | Line Height | Phase-12 usage |
|------|------|--------|-------------|----------------|
| Body | 16px (1rem) | 400 | 1.5 | stub-page optional "Coming in Phase 14" subline (muted) |
| Label | 14px (0.875rem) | 400 | 1.4 | nav row labels (primitive `text-sm`); footer "Running" label |
| Heading | 20px (1.25rem) | 600 | 1.2 | stub-page `<h1>` heading placeholders (Series / Series Detail / Movies) |
| Display | 28px (1.75rem) | 600 | 1.1 | not used in Phase 12 |

**Brand pill "TREZARR":** rendered uppercase at Label size (14px) weight 600,
with `tracking-wide`/letter-spacing for the pill look. Uppercase is a CSS transform
(`uppercase`) or literal capitals — it is NOT a new font weight and does not breach
the 2-weight contract.

**Active nav weight note:** the vendor primitive applies `font-medium` (500) to the
active item via `data-[active=true]:font-medium`. This is shadcn-internal vendor
styling on a primitive we do not edit; the *visual* active signal in this contract
is the purple accent bar + accent background, not the weight. The 500 weight is a
documented vendor exception confined to `ui/sidebar.tsx`; it does not authorize a
third weight in hand-written app code.

## Interaction Contract (phase-defining — read carefully)

This is the load-bearing section for Phase 12. The executor must implement these
behaviors in the **hand-written `frontend/src/components/app-sidebar.tsx`** and the
thin **`frontend/src/components/AppShell.tsx`** wrapper — never by editing
`src/components/ui/sidebar.tsx`.

### 1. Shell composition (D-04, ARCHITECTURE.md §2)

```
<SidebarProvider>              // whole-document context; manages open/collapsed + cookie
  <AppSidebar />               // hand-written; collapsible="icon"
  <main className="flex-1 overflow-auto bg-background p-6">
    <Outlet />                 // routed page renders here (replaces children prop)
  </main>
</SidebarProvider>
```

`AppShell.tsx` moves from a `children`-prop wrapper to an `<Outlet/>` host nested
under a single react-router layout route `<Route path="/" element={<AppShell/>}>`.
Verified safe: no test file mounts `<AppShell>` (CONTEXT.md §Integration Points).

### 2. Active-state accent bar — CRITICAL VENDOR GAP (D-05, NAV-01)

**Finding (verified in vendor source):** the installed `sidebar.tsx`
`SidebarMenuButton` implements `data-[active=true]` as a FILLED background
highlight (`data-[active=true]:bg-sidebar-accent data-[active=true]:font-medium
data-[active=true]:text-sidebar-accent-foreground`, line 523). The stock primitive
does **NOT** render the promised "left 2px purple accent bar." NAV-01 and the
Phase-11 contract both require that bar.

**Contract — the executor MUST add the accent bar via a `className` on
`SidebarMenuButton` in `app-sidebar.tsx` (NOT by editing the vendor file):**

Apply, on each `SidebarMenuButton`, a conditional left-border that lights up purple
on active:

```
className="border-l-2 border-transparent data-[active=true]:border-sidebar-primary"
```

(Equivalently `data-[active=true]:border-l-2 data-[active=true]:border-sidebar-primary`
with a transparent/zero default to avoid a layout shift.) The bar uses
`--sidebar-primary` (purple). The primitive's filled-accent background + `font-medium`
remain and COMPOSE WITH the bar — the active row reads as: purple left bar + subtle
purple-tinted background. This reproduces the exact look of the legacy AppShell
(`border-l-2 border-accent bg-bg-stripe`) on the new mechanism, as CONTEXT.md
§code_context states ("the look carries over, the mechanism changes").

**Collapsed (icon-rail) active state:** when collapsed to 48px, the accent bar still
renders on the left edge of the active icon button (border-l survives the icon-only
layout). The label is hidden; the bar + tinted background remain the active signal.

### 3. Active-route matching — prefix logic (D-05, §specifics)

Derive active state inside `app-sidebar.tsx` from react-router `useLocation`, and
pass it to `SidebarMenuButton`'s `isActive` prop:

```
isActive = (pathname === to) || pathname.startsWith(to + "/")
```

This keeps `/series` active on `/series/:seriesId` and `/bible` active on
`/bible/:seriesId`. Navigate with `onClick={() => navigate(to)}` — NOT `asChild` +
`<a>` (preserves client-side routing without fighting the Radix slot model).

### 4. Nav items — locked, exactly six, in this order (NAV-02, D-06)

| Order | Label | Route (`to`) | lucide icon |
|-------|-------|--------------|-------------|
| 1 | Series | `/series` | `Tv` |
| 2 | Movies | `/movies` | `Film` |
| 3 | Queue | `/queue` | `List` |
| 4 | History | `/history` | `History` |
| 5 | Bible | `/bible` | `BookOpen` |
| 6 | Settings | `/settings` | `Settings` |

`/library` is NOT a nav item (D-03 — kept reachable as a transitional route only,
removed Phase 14). Nav labels are exactly these strings (locked Phase-11 §Copywriting).

### 5. Collapse / expand behavior (D-01)

| Aspect | Contract |
|--------|----------|
| Mode | `collapsible="icon"` on `<Sidebar>` |
| Default state | expanded |
| Persistence | shadcn built-in cookie `sidebar_state` (vendor default; no custom store) |
| Primary toggle | `SidebarRail` (draggable edge) + `Cmd/Ctrl+B` keyboard shortcut (vendor default `"b"`) |
| Optional toggle | a `SidebarTrigger` in the `SidebarHeader` is permitted (Claude's discretion; chosen ON for ergonomics since the TopBar is gone) |
| Collapsed nav | icons only, labels hidden (48px rail); active accent bar still shows |
| Mobile / narrow | shadcn auto-`Sheet` (288px); not a primary target but must not break |

### 6. Brand header (D-06, NAV-01)

`SidebarHeader` contains: lucide `Captions` glyph tinted `text-sidebar-primary`
(purple) + an uppercase "TREZARR" pill (14px / weight 600 / `uppercase` /
`tracking-wide`). When collapsed to the icon rail, show ONLY the glyph; hide the pill.
`Languages` is an approved alternate glyph if `Captions` reads poorly at 16–20px —
finalize at the UI verify gate (Claude's discretion, D-06).

### 7. Footer status row (D-02)

`SidebarFooter` contains a row: a green dot (`bg-[#22c55e]`, ~8px,
`aria-label="Service status: running"`) + a "Running" label (14px, muted). When
collapsed, show ONLY the dot (label hidden), consistent with the icon-only state.
Semantics in Phase 12: static "the server is serving this page" indicator. It is NOT
wired to *arr connection state — that LIVE badge is NAV-03 / Phase 14. Do not over-build.

### 8. Stub pages (Success Criterion 4, Claude's discretion)

`Series.tsx`, `SeriesDetail.tsx`, `Movies.tsx` render a single `<h1>` heading
placeholder (Heading role: 20px / 600) and an optional muted "Coming in Phase 14"
subline (Body role: 16px / 400 / `text-muted-foreground`). Must compile under
`strict` + `noUnusedLocals`/`noUnusedParameters` and render with no console errors.
Suggested headings: "Series", "Series", "Movies" respectively (SeriesDetail may show
"Series Detail" or echo the `:seriesId` param).
