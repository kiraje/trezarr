# Quick Task 260603-l8g — Library browser + manual single-item translate (arr-themed)

**Gathered:** 2026-06-03
**Status:** Locked design — approved by user this session. Do NOT re-interrogate.

## Why

Trezarr was built daemon-first: discovery is entirely *arr-poll-driven and the only
translation path is "the scheduler finds everything eligible and translates the whole
library." There is NO UI to see what shows exist and NO way to translate exactly one
chosen item. The user needs to hand-pick ONE show/episode (or movie) and translate it as a
controlled test — without the poller mass-translating their paid LLM endpoint.

## Locked design (verified against the codebase this session)

### Backend (new routes under `trezarr/web/routes/`, register in `trezarr/web/app.py`)

1. **`GET /api/library`** — list Sonarr series + Radarr movies.
   - Series: `build_sonarr_client(settings).series.get()`; Movies: `build_radarr_client(settings).movie.get()`.
   - Per item: `kind` ("series"|"movie"), arr id, `title`, `year`, `monitored`, poster URL if available;
     for movies also resolve local source-sub status.
   - Gate each source on `settings.sonarr_enabled` / `settings.radarr_enabled`. If a source is
     disabled or its API errors, return that section EMPTY with a per-source error note — never 500.
   - Reuse `trezarr/arr/sonarr.py` + `radarr.py` clients and `_normalize_arr_host`.

2. **`GET /api/library/series/{id}/episodes`** — episodes for ONE Sonarr series (read-only; no translation).
   - `client.episode_file.get(series_id=id)` + episode metadata.
   - Per episode: episode key (SxxExx via existing `derive_episode_key` / filename parse), title,
     path-mapped `local_path`, source-sub present? (`trezarr/discover/scan.py::find_source_sub` with
     `settings.source_lang_priority`), `source_lang`, already-translated? (vi sidecar exists OR ledger
     `ProcessedFile` status=done — reuse `is_eligible` / ledger lookup).
   - Status enum: `translated | has_source | nothing`.

3. **`POST /api/translate`** — body `{ kind, arr_series_id?, episode_id? | source_sub_path? }`.
   - Resolve to a concrete `source_sub_path` + `MediaItem` (reuse `discover/find_source_sub` + the
     arr `MediaItem` build path).
   - REFUSE (400) if no source sub exists for the item.
   - Enqueue EXACTLY ONE job via existing `trezarr/web/worker.py::enqueue_job(session_factory,
     source_path, series_id, trigger="manual", media_item=...)`. Return `{ job_id, status: "enqueued" }`.
   - Reuses existing `worker_loop -> _execute_job -> process_one_item`. **Do NOT add a
     blocking/synchronous translate path.** Single-item only via enqueue.

### Safety (critical — must NOT mass-translate the user's paid endpoint)

4. **Bug 3 fix** — in the settings save path (`trezarr/web/config_writer.py` / `routes/settings.py`),
   when a connection's host + api_key are BOTH non-empty, set the corresponding
   `sonarr_enabled` / `radarr_enabled` / `bazarr_enabled` = true so discovery/listing works.

5. **New master switch** `auto_translate_enabled: bool = False` in `trezarr/config.py`.
   - Gate the scheduled poller `trezarr/web/scheduler.py::poll_and_enqueue` on
     `settings.auto_translate_enabled` IN ADDITION to the existing per-source `*_enabled` checks.
   - Effect: enabling a connection lets the user browse + hand-pick, but the daemon NEVER
     auto-sweeps the whole library until the user explicitly flips `auto_translate_enabled` on.
   - Surface this toggle in the Settings UI (default OFF, with a clear warning label:
     "automatically translate eligible library on a schedule").
   - It's a config.yaml / settings field — likely NO DB migration needed.

### Bug fix (high value for this exact test workflow)

6. **Bug 2** — `alembic/env.py`: change `fileConfig(config.config_file_name)` to
   `fileConfig(config.config_file_name, disable_existing_loggers=False)` so `trezarr.*` loggers are
   NOT silenced after migration runs at daemon startup. Without this, a failed test translation
   shows only `failed=N` with no reason — defeating the whole point of a controlled test.

### Frontend (`frontend/src` — React 19 + Vite + Tailwind)

Existing dark theme tokens (`tailwind.config.js`): `bg-base #0f1117`, `bg-surface #1a1d27`,
`bg-stripe #1e2130`, `border #2d3148`, `text-primary #e2e6f0`, `text-muted #6b7280`, `accent #3b82f6`.

7. New page `frontend/src/pages/Library.tsx` + route in `App.tsx` + sidebar `NavItem` in
   `components/AppShell.tsx` (lucide-react icon, e.g. `Film`/`Tv`, label "Library").
   - Top level: list of shows + movies in the *arr (Servarr) idiom — poster thumbnail if available,
     title, year, kind badge; striped+hover rows (`bg-stripe`) consistent with existing tables.
   - Click a series → drill into its episodes (`GET /api/library/series/{id}/episodes`); each row
     shows episode key + title + a STATUS PILL: green "Translated" / blue "Has source" / grey
     "No source". A "Translate" button enabled only when status=`has_source`; clicking POSTs
     `/api/translate` then navigates to `/queue` so the user watches it in the existing
     Queue/History/JobLogs UI.
   - Movies are leaf items: Translate button directly.
   - Add typed fetch wrappers to `frontend/src/api/client.ts` (native fetch, existing patterns).
     The existing 5s timeout is too short for live *arr list calls — use ~30s for library endpoints.
   - Keep accent blue (`#3b82f6`). Reuse `StatusBadge` + established page-header + table patterns.
