<objective>
Deliver two changes that together eliminate the confirmed IMP-02 quarantine class and provide a local
fast-feedback loop:

1. Replace the "re-send identical prompt N times" tenacity retry in Pass-3 batch translation with a
   bounded message-accumulating correction loop (the ContextWeave validated_chat pattern). When the LLM
   drops a line, the conversation grows: the bad assistant reply is appended, then a structural-only
   correction user turn is appended, and the LLM is called again — up to
   translate_batch_retry_attempts total retries. The original prompt in messages[0] stays authoritative
   and is never re-emitted or paraphrased, protecting the pronoun-hint moat.

2. Add scripts/translate_one.py — a dev-only CLI that calls the real pipeline locally so a
   validate-locally loop is minutes, not a 16-minute server deploy cycle.

Purpose: Close IMP-02 ("a single mis-counted batch quarantines the episode") from the ContextWeave
benchmark audit. Ep-142 QUARANTINED after 16 minutes on a non-deterministic dropped line from DeepSeek;
the existing tenacity retry re-sent the identical prompt with no feedback. The correction loop turns
the LLM's own error into a self-correcting conversation.

    DESIGN of the new _translate_batch_inner:

    a) Remove BatchValidationError from the tenacity @retry decorator's retry_if_exception_type.
       The decorator stays (it still handles transport-level retries if any are left in its scope),
       but its retry predicate must no longer catch BatchValidationError. The cleanest approach is
       to change the decorator to retry on a never-raised sentinel type
       (e.g. retry_if_exception_type(TranslationError) where TranslationError is never raised inside
       _translate_batch_inner) so tenacity is effectively a no-op for batch validation failures, OR
       remove the tenacity decorator entirely and replace it with a plain loop. Prefer removing
       tenacity from this function entirely — the decorator was only needed for the retry-on-error
       pattern, which the correction loop now owns. The stop_after_attempt bound is no longer needed
       because the loop itself is bounded by `attempts`.

       NOTE: _translate_batch (the public wrapper at line ~835) calls
       _make_translate_batch_fn(settings) and then calls the returned function. After this change
       the inner function is a plain async def (no decorator), and the wrapper calls it directly.
       Update the docstring accordingly.

    b) The body of _translate_batch_inner becomes a correction loop:

       Compute `attempts = settings.translate_batch_retry_attempts + 1` (same formula as before —
       total LLM calls = 1 initial + N retries).

       Step 1: Extract sentinels, build prompt (unchanged).
       Step 2: Initialize messages = [{"role": "user", "content": prompt}].
       Step 3: Loop up to `attempts` times:
         - Call raw_response = await llm_client.call(messages, model=model)
         - Try parse_numbered_response + sentinel reinsert (unchanged validation logic).
         - On success: return restored (unchanged).
         - On BatchValidationError as exc:
             - If this was the last allowed attempt: raise (propagates to translate_file → quarantine).
             - Otherwise: build correction_turn (see below) and append to messages:
                 messages.append({"role": "assistant", "content": str(raw_response)})
                 messages.append({"role": "user", "content": correction_turn})
             - Continue to next loop iteration.

    c) The correction turn (correction_turn):

       Build a module-level constant template _STRUCT_CORRECTION_MSG and format it per-call:

         _STRUCT_CORRECTION_MSG = (
             "Your response had a structural error: {defect}. "
             "I need EXACTLY {n} lines, numbered [1] through [{n}], one per source line, in order. "
             "Do NOT skip any number. Keep every <<T0>>/<<BR>> token exactly as in my first message. "
             "Follow ALL rules, the GLOSSARY, the REGISTER, and any "
             "'(speaker says: ...; addresses as: ...)' hints from my FIRST message. "
             "Output ONLY the {n} numbered lines."
         )

       where `defect` is str(exc) (the BatchValidationError message, e.g. "Missing line [1] in LLM
       response (expected 4 lines)") and `n` is len(batch.cues).

       MOAT INVARIANT: the correction turn references hints as "from my FIRST message" — it NEVER
       re-emits, quotes, or paraphrases any pronoun pair. The pronoun hints live in messages[0]
       (the original prompt from build_translate_prompt) and are carried forward by the LLM's own
       conversation context. Do NOT include any (speaker says: ...) content in the correction turn.

    d) The sentinel reinsert step (Step 5 in the original) moves inside the try block after
       parse_numbered_response. A sentinel integrity failure raises BatchValidationError (unchanged)
       and is treated identically — it triggers the correction loop. This is correct: a bad sentinel
       is also a structural failure the LLM can correct with feedback.
