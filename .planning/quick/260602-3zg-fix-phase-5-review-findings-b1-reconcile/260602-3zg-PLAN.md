<objective>
Fix two verified Phase-5 review defects (B1 BLOCKER + M1 MEDIUM) that together silently
drop pronoun pairs and fork Character rows.

Purpose: These two defects directly undermine the project's core value — consistent,
relationally correct pronouns. B1 causes whitespace-padded or case-variant LLM names
to miss the reconcile lookup entirely, silently falling to safe-default and emitting the
wrong relationship register. M1 compounds this across episodes by allowing the same
character to exist as two separate DB rows whenever the LLM casing/whitespace varies.

Output:
  - reconcile.py — 3 lines changed (.strip().lower() at index build + both lookups)
  - store.py — _upsert_character_in_session and get_character use case-insensitive
    comparison (SQLAlchemy func.lower) while preserving stored display-case name
  - Two new regression tests (one per fix) confirming the silent-drop and row-fork paths
    no longer occur

Decision note on M1 display-name policy: preserve the originally stored display-case name
in the DB column; compare using func.lower(...) == name.strip().lower() so identity
resolution is case/whitespace-insensitive without clobbering the human-readable name.
This matches how in-memory resolution works everywhere else (attribute.py, engine.py,
analyze.py all use .strip().lower() on the in-memory DTO — the DB must enforce the same
boundary or cross-episode runs fragment the address map).
</objective>
