# v1.0 Translation-Pipeline Verification — Findings (2026-06-04)

Triggered while closing v1.1: an attempt to verify v1.0's **core value** (consistent,
relationally-correct Vietnamese subtitles) on real output, since **0 `.vi.srt` had ever been
produced** on the live deployment. Verified by translating one real episode — *Agents of the
Four Seasons: Dance of Spring* S01E06 (Chinese source, song-heavy) via the live deepseek
endpoint.

## Outcome: core value NOT verified — pipeline runs but the model is insufficient

The live run surfaced **5 real pipeline bugs**. 4 were fixed (the pipeline now runs the full
3-pass end-to-end); the 5th + the model-suitability finding are the documented debt.

### Root-cause conclusion: `deepseek-v4-pro` is too weak for this pipeline
Every remaining failure is the same root cause — a weak instruction-follower tripping the
(correct) fidelity gates:
- Needed a json-mode workaround (#2).
- **Hallucinated sentinel/formatting tokens** into untagged lines (#5).
- **24 self-review "sentinel integrity failures"** on one episode (engine fell back to
  pre-review output via D-59, as designed).
- Pass-1 analyze persisted **0 Bible characters** for the series (no usable structured output
  from the model on this content).

`CLAUDE.md` already prescribes a **frontier model** for the "replace a human translator" bar
("prefer instructing the user toward a frontier model that supports strict structured
outputs"). This run is empirical confirmation: deepseek-v4-pro on a proxy endpoint cannot drive
the pipeline to a trustworthy result. Patching more gate edge-cases will not fix the model.
