### Badge Color Token Mapping (D-06 — load-bearing)

Badge colors are expressed ONLY as CSS variable references + Tailwind utility classes.
Never use raw hex inside component code.

| Badge type | Background class | Text class | Approx color | Meaning |
|------------|-----------------|------------|--------------|---------|
| Audio language | `bg-blue-700/80` | `text-white` | ~`#1d4ed8` at 80% | Audio track language code (e.g. `KO`, `EN`) |
| Source subtitle (amber) | `bg-amber-600/80` | `text-white` | ~`#d97706` at 80% | Non-VI subtitle track (source/foreign) |
| Vietnamese subtitle (purple) | `bg-[hsl(var(--primary))]/80` | `text-primary-foreground` | ~`#8b5cf6` at 80% | VI or VI:HI subtitle track |
| LIVE badge (sidebar) | `bg-emerald-600` | `text-white` | ~`#059669` | *arr service connected |
| Count badge (sidebar) | `bg-[hsl(var(--primary))]` | `text-primary-foreground` | ~`#8b5cf6` | Count of series/movies needing VI |

**Why `bg-blue-700/80` for audio (not a CSS var):** There is no `--audio` semantic token in
the purple theme. `blue-700` at 80% opacity is the closest Tailwind built-in that reads
clearly on dark backgrounds and is visually distinct from amber and purple. This is a
discretionary choice (CONTEXT.md §Claude's Discretion). The executor MAY substitute
`bg-sky-700/80` if blue-700 reads too dark against `--background`.

**Why opacity (`/80`) on subtitles and audio:** Badge clusters on an episode row can contain
3+ badges. Slight transparency reduces the visual weight of the cluster while maintaining
legibility of the label text.

### Accent reservation for Phase 14

`--primary` (purple) is reserved for EXACTLY these elements in Phase 14 (extends Phase-11
reservation):

- VI subtitle badge background (`bg-[hsl(var(--primary))]/80`)
- Sidebar nav count badge background (items needing VI translation)
- `<Button variant="default">` — the Translate button
- Existing reservations: active nav left bar, brand glyph tint, focus rings (unchanged)

Accent must NOT be used for: audio badges, source (amber) badges, LIVE badge, table
headers, progress bar fill (use `bg-primary` at 60% width for the bar — see Progress Bar),
episode title text.

### Progress Bar

The `translated/total` progress indicator on Series + Movies list rows:

- Container: `bg-muted` (full-width, height `h-1.5`, `rounded-full`)
- Fill: `bg-primary` (width = `${(translated_count / total_count) * 100}%`, `rounded-full`)
- When `total_count === 0`: show `—` (em dash) instead of a bar and fraction
- When `translated_count === total_count && total_count > 0`: fill is 100% (fully translated)
- The fill bar uses `bg-primary` (purple) — this is a checked/selected state indicator, an
  existing Phase-11 reservation for `--primary`

## API Data Flow Contract

### GET /api/library

**Response shape (from library.py):**
```typescript
interface LibraryResponse {
  series: SeriesItem[];
  movies: MovieItem[];
  errors: Array<{ source: string; error: string }>;
}

interface SeriesItem {
  kind: "series";
  id: number;
  title: string;
  year: number | null;
  monitored: boolean;
  poster_url: string | null;
  translated_count: number;   // episodes with VI sidecar (ledger count)
  total_count: number;        // episodeFileCount from Sonarr statistics
}

interface MovieItem {
  kind: "movie";
  id: number;
  title: string;
  year: number | null;
  monitored: boolean;
  poster_url: string | null;
  source_sub_found: boolean;
  translated_count: number;   // 1 if vi sidecar exists, 0 otherwise
  total_count: number;        // 1 if hasFile, 0 otherwise
}
```

**LIVE badge derivation (D-10):**
- `sonarr_live = sonarr_enabled AND !errors.some(e => e.source === "sonarr")`
- `radarr_live = radarr_enabled AND !errors.some(e => e.source === "radarr")`
- The response does NOT contain `sonarr_enabled`/`radarr_enabled` flags — the UI infers
  connectivity from errors[]: if the series list is non-empty with no sonarr error, Sonarr
  is live. If series list is empty AND there is a sonarr error, Sonarr is down.
- **Concrete rule:** Series nav LIVE = `series.length > 0 || !errors.some(e => e.source === "sonarr")`.
  Movies nav LIVE = `movies.length > 0 || !errors.some(e => e.source === "radarr")`.
  (An empty library with no errors still means the service is live.)

**Count badge derivation (D-09):**
- Series count = `series.filter(s => s.translated_count < s.total_count).length`
- Movies count = `movies.filter(m => m.translated_count < m.total_count).length`
- Both auto-hide at zero (render nothing, not a `0` badge)

**Data sharing:** The Series list page fetches `GET /api/library` for its own table.
The sidebar reads the SAME data. Two approaches are acceptable:
1. The sidebar subscribes to the same data via a shared React context (preferred — avoids
   a second fetch).
2. The sidebar fetches independently on a polling interval (simpler but doubles requests).

**Decision (discretionary):** Use a minimal React context (`LibraryContext`) that the
Series/Movies pages populate on their fetch, and the sidebar consumes for badge counts.
If the Series page is not yet mounted (user starts on `/queue`), the sidebar shows no
count badges (zero = hidden, correct behavior). No polling in the sidebar itself.

### GET /api/library/series/:id/episodes

**Response shape (from library.py — the Phase-13 SeriesEpisodesResponse envelope):**
```typescript
interface SeriesEpisodesResponse {
  series_id: number;
  bazarr_available: boolean;
  seasons: SeasonGroup[];
  errors: Array<{ source: string; error: string }>;
}

interface SeasonGroup {
  season_number: number;
  episodes: EpisodeEnrichedRow[];
}

interface EpisodeEnrichedRow {
  episode_id: number | null;
  episode_file_id: number | null;
  season_number: number;
  episode_number: number;
  episode_key: string;          // "S01E01" format
  title: string;
  monitored: boolean;
  has_file: boolean;
  local_path: string | null;
  source_path: string | null;
  source_lang: string | null;
  status: "nothing" | "has_source" | "translated";
  audio_languages: string[];    // ISO-639-1 code2 list, e.g. ["ko", "en"]
  subtitles: SubtitleEntry[];
}

interface SubtitleEntry {
  code2: string;               // e.g. "vi", "en", "zh"
  code3: string;               // e.g. "vie", "eng"
  hi: boolean;                 // hearing-impaired
  forced: boolean;
}
```

**useParams typing (IN-01 carry-forward):** Use `useParams<{ seriesId: string }>()`.
Guard before fetch: `if (!seriesId) return <div>Invalid series</div>`. Convert to int:
`const id = parseInt(seriesId, 10); if (isNaN(id)) return <div>Invalid series ID</div>`.

### POST /api/translate

**Request body:**
```typescript
interface TranslateRequest {
  kind: "series" | "movie";
  source_path: string;
  arr_series_id?: number;
}
```

**On success:** `{ enqueued: boolean, source_path: string }`. After receiving a truthy
`enqueued`, call `navigate("/queue")`.

**Error handling:** If the POST returns 400 (`source_sub_not_found` or
`source_path_required`), show an inline error message on the row — do NOT navigate.

Enqueues ALL episodes in the season where `has_file === true && source_path !== null &&
status !== "translated"`. Calls `POST /api/translate` for each, sequentially (not
`Promise.all` — respect the semaphore pattern). After the last call, `navigate("/queue")`.
No confirmation dialog (discretionary choice — the Queue page shows all pending items,
and the user can cancel from there; an extra modal adds friction for a power-user action).

## SubtitleBadge Component Contract

`src/components/SubtitleBadge.tsx` — hand-written, reusable by Phase-15 reskin.

**Props:**
```typescript
interface SubtitleBadgeProps {
  code2: string;        // uppercase ISO-639-1 code for display ("VI", "EN", "KO")
  hi?: boolean;         // hearing-impaired — appends ":HI"
  forced?: boolean;     // forced subtitle — appends ":Forced"
  type: "audio" | "source" | "vi";
}
```

**Label construction:**
- Audio: `code2.toUpperCase()` (e.g. `KO`)
- Source/foreign subtitle: `code2.toUpperCase()` (e.g. `EN`), plus `:HI` if `hi=true`,
  `:Forced` if `forced=true` (e.g. `EN:HI`, `EN:Forced`, `EN:HI:Forced` if both)
- VI subtitle: `VI` or `VI:HI` or `VI:Forced` as above
- The classification rule: `type === "vi"` when `code2.toLowerCase() === "vi"`;
  `type === "audio"` when passed from `audio_languages` array; `type === "source"` otherwise

**Color classes by type:**
- `audio`: `className="bg-blue-700/80 text-white border-transparent"`
- `source`: `className="bg-amber-600/80 text-white border-transparent"`
- `vi`: `className="bg-[hsl(var(--primary))]/80 text-primary-foreground border-transparent"`

**Non-color accessibility (D-07 — mandatory):**
Each badge includes BOTH a shape cue AND an aria-label:
- Shape cue: a leading filled dot (`●`, `aria-hidden="true"`, 6px, same color as badge text)
  visually distinguishes badge types when color is unavailable. Audio = no dot prefix (icon
  differentiates). Alternatively: prefix audio badges with a lucide `Volume2` icon (size 10).
  Decision: use the lucide `Volume2` icon (size 10, `aria-hidden`) for audio and a filled dot
  for source/VI. This is the discretionary shape cue choice.
- `aria-label` on each badge `<div>`: format `"{language name} {type}, {flags}"` e.g.
