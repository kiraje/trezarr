## CSS Variable Theme Contract

### Canonical Rule: Channel-Triple Format (D-02)

ALL CSS variable values in `src/index.css` are bare `H S% L%` channel triples.
NO `hsl()` wrapper inside the CSS variable. The `hsl(var(--x))` wrapper lives
exclusively in `tailwind.config.js`.

Violation: `--primary: hsl(270 70% 60%)` — silently breaks `bg-primary/50` with no compile error.
Correct:   `--primary: 270 70% 60%`

### Bridge Token Policy (D-05)

The following five legacy hex tokens STAY in `tailwind.config.js` during the bridge period.
They do NOT collide with shadcn's namespace. Remove them only in Phase 15 after all pages reskinned.

| Bridge Token Class | Legacy Hex | Pages Using It |
|---|---|---|
| `bg-base` | `#0f1117` | AppShell and all existing pages |
| `bg-surface` | `#1a1d27` | Cards, panels on existing pages |
| `bg-stripe` | `#1e2130` | Table rows, alternating backgrounds |
| `text-primary` | `#e2e6f0` | Default body text on existing pages |
| `text-muted` | `#6b7280` | Secondary text on existing pages |

The colliding keys from the old config — `border`, `accent`, `destructive` — are replaced
wholesale with shadcn CSS-var-backed entries in the new `tailwind.config.js`. (D-05)

## Color

Phase 11 establishes the full color contract via CSS variables. The 60/30/10 breakdown
maps onto the shadcn token roles as follows:

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) — page root | `hsl(270 24% 7%)` approx `#100d17` | `--background`: page root, behind all panels | D-04; RESEARCH.md token table |
| Dominant (60%) — bridge surfaces | `#0f1117` / `#1a1d27` / `#1e2130` | `bg-base`, `bg-surface`, `bg-stripe`: existing page panels (bridge period) | D-05 |
| Secondary (30%) | `hsl(270 22% 11%)` approx `#19151f` | `--card`, `--popover`: shadcn card/modal surfaces | RESEARCH.md token table |
| Accent (10%) | `hsl(270 70% 60%)` approx `#8b5cf6` | `--primary`, `--ring`, `--sidebar-primary`, `--sidebar-ring`: see reserved list | D-01, D-03 |
| Destructive | `hsl(0 72% 51%)` approx `#e03131` | `--destructive`: destructive actions only | D-03 |

Accent (`--primary`) reserved for EXACTLY these elements:
- `<Button variant="default">` background
- Active nav item highlight (`--sidebar-primary`)
- Focus rings (`--ring`, `--sidebar-ring`)
- Checked/selected state indicators on shadcn primitives
- Phase 12 left purple accent bar on active nav item (contract for that phase)

Accent must NOT be used for: informational text, generic borders, non-interactive decorative elements.

## Wiring Invariants

These are the non-negotiable build constraints for Phase 11 (from D-08):

| Invariant | Value | Why It Must Not Change |
|-----------|-------|------------------------|
| `vite.config.ts` has no `base` field | unset | Breaks FastAPI StaticFiles absolute-path asset serving from root mount |
| `build.outDir` | `../trezarr/web/static` | FastAPI serves Vite build from this path |
| `build.emptyOutDir` | `true` | Cleans stale assets on rebuild |
| `@/` alias wired in BOTH configs | `vite.config.ts` resolve.alias + `tsconfig.json` paths | Partial alias causes tsc/vite asymmetric failures |
| `tsconfig.json` `baseUrl` | `.` (frontend root) | Required for `paths` to resolve `@/*` → `./src/*` |
| `darkMode` strategy | `["class"]` not `"media"` | Forced-dark app; media-query strategy ignores `.dark` class |
| `class="dark"` location | On `<html>` element in `index.html` | Inline attribute, no JS flash on load |
| shadcn init pin | `shadcn@2.10.0` | @latest is v4 CLI — emits Tailwind v4 config that breaks PostCSS pipeline |
| shadcn add | `shadcn@latest` is safe for `add` only | Component source-file copy only; does not re-run init |
| `.npmrc` timing | Created BEFORE first `shadcn add` | After-the-fact `.npmrc` does not prevent ERESOLVE |
| `legacy-peer-deps` method | `.npmrc` file, not `--force` | `--force` causes subtle runtime breakage |
| `src/components/ui/` | Vendor code — never hand-edit | CLI-generated; hand edits diverge from shadcn baseline |

## Phase-End Verification Contract (D-09)

Phase 11 ends with a human visual-UAT checkpoint. The `--auto` chain HOLDS at this gate.

### Build Gate (automated)

```bash
cd frontend && npm run build
# Must: exit 0, tsc -b clean, vite build clean, trezarr/web/static/ populated
```

```bash
grep -l "animate-in" dist/assets/*.css
# Must: match at least one file (proves tailwindcss-animate in plugins)
```

### Browser UAT Gate (human — D-09)

Three proofs required before Phase 11 may close:

1. **Dark purple background**: DevTools Elements shows `<html class="dark">`. Body background-color computed value is approximately `hsl(270, 24%, 7%)` (dark purple, not `#0f1117` blue-black).

2. **Purple Button renders**: A `<Button variant="default">` from `src/components/ui/button.tsx` is placed on any route and renders with a purple background matching `--primary`.

3. **Opacity modifier proof** (canonical channel-triple format validation):
   ```html
   <div class="bg-primary/50 w-16 h-16 fixed top-4 right-4 rounded"></div>
   ```
   Must render as semi-transparent purple (half-opacity). Full-opacity or invisible = channel-triple format violated (Pitfall 1).

4. **No broken pages**: All existing pages (`/queue`, `/history`, `/settings`, `/bible`) load and render without white/unstyled content.
