<objective>
Stand up the SQLAlchemy 2.0 async + aiosqlite + Alembic persistence backbone for Phase 4. Install the three new packages, build the engine/session/migration scaffolding, hand-author a single baseline Alembic migration that creates all seven long-term Bible tables (D-31), define the SQLAlchemy 2.0 typed models behind a `DeclarativeBase` root, extend `TrezarrSettings` with the Phase-4 DB-URL fields, and create the test fixtures + smoke tests proving the migration produces all 7 tables with the right PRAGMAs enforced per-connection. No store API, no merge logic, no JSON-ledger migration — those are 04-02/03/04. This plan unblocks all of them.

Task ordering note (revision): the foundation is delivered as ONE atomic unit in Task 1 (scaffolding + models + baseline migration + conftest + PRAGMA tests). Splitting "scaffold first, models second" would force a coordination dance where Task 1 ships commented-out env.py imports and conftest fixtures that `pytest.skip()` until Task 2 lands — that path was rejected on revision because it gives a misleading "green tests" signal at Task 1 commit time. Task 2 here is exclusively the model-fidelity round-trip + UNIQUE-constraint + downgrade tests — verification depth, not scaffolding.

Purpose: Plans 04-02, 04-03, and 04-04 all depend on a working engine + migrated schema + DTO/model layer. Centralising the bootstrapping in one plan keeps the three downstream plans focused on their respective slices (series/register, character/term/merge, ledger swap).

Output: Working `trezarr/db/` + `trezarr/bible/models.py` + Alembic scaffolding + a clean test suite that proves: (1) packages installed, (2) PRAGMAs apply per-connection, (3) baseline migration creates 7 tables, (4) round-tripping a Series/Character/TermDictionary row works.
</objective>
