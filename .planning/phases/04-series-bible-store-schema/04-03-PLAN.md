<objective>
Deliver the character + term + merge slice that puts the consistency engine substrate in place. Build the pure-Python lock-precedence policy (`trezarr/bible/merge.py`) and extend `trezarr/bible/store.py` with `get_character`/`get_term`/`upsert_character`/`upsert_term`/`merge_inferred` plus their private session-scoped helper counterparts. The crown jewel is `merge_inferred`: it enforces `human lock > prior value > new inference` (D-34, success criterion 4), it writes the current-row UPDATE and the bible_event row(s) in ONE transaction (D-32), derives locked and changes from a FRESH row re-read inside the transaction (not the caller's stale DTO), and it is exhaustively tested for lock survival, no-op detection, atomicity-on-failure, carry-forward semantics (BIBLE-06), nested-transaction prevention, whitelist enforcement, first-insert events, and clearing-to-None.

Cross-AI review HIGH findings incorporated:
1. `merge_inferred` re-reads the row inside the transaction and derives BOTH `locked` and `changes` from the fresh row state — never from the caller's DTO. The pure `compute_field_changes(entity_dto, ...)` helper still exists for policy unit tests, but the actual call site inside `_merge_inferred_in_session` passes a fresh DTO or snapshot built from the DB row inside the transaction. This guarantees correct `old_value` audit entries even if the DB row changed after the caller loaded their DTO.
2. `upsert_character` / `upsert_term` must NOT call public `merge_inferred(...)` from inside their own transaction. Private session-scoped helpers `_merge_inferred_in_session(session, row, inferred, episode_key, source)`, `_upsert_character_in_session(session, ...)`, and `_upsert_term_in_session(session, ...)` are introduced. Public `upsert_*` and public `merge_inferred` are the ONLY transaction owners.

Purpose: This is the policy substrate Phase 5's LLM Pass-1 will call when it has new character/term inferences from a translated episode. The merge contract guarantees that locked corrections never get overwritten by silent inference drift, that unchanged inferences produce zero audit churn, and that the audit trail (bible_event) cannot become inconsistent with the current state. Without these guarantees, the entire Series-Bible-as-consistency-engine value proposition fails.

    ```
    def get_locked_fields(entity_dto: Any) -> frozenset[str]:
        """Read locked_fields off any DTO/object that carries the convention.

        Defensive — returns frozenset() if the attribute is missing. Phase 8 may
        swap entity_dto.locked_fields for a database-side lookup; the only
        contract this function exposes is "give me the set of locked field names
        for this entity."
        """
        return frozenset(getattr(entity_dto, "locked_fields", []) or [])
    ```

    ```
    def compute_field_changes(
        entity_dto: Any,
        inferred: dict[str, Any],
        locked: frozenset[str],
    ) -> list[tuple[str, Any, Any]]:
        """Return [(field, old, new), ...] for fields that should actually change.

        Skips fields in `locked` (human lock wins — D-34 / success criterion 4).
        Skips no-op fields where inferred == current (D-32 / BIBLE-06 carry-forward).
        Treats a missing attribute on entity_dto as old_value=None.
        Accepts new_value=None (clearing a field) as a genuine change.

        Pure function — no DB, no side effects. Easy to unit test exhaustively.

        IMPORTANT: In store.py, always call this with a DTO built from the FRESH
        DB row read inside the transaction, not the caller's stale DTO. This
        function itself has no such constraint, but the call site must enforce it.
        """
        changes: list[tuple[str, Any, Any]] = []
        for field, new_val in inferred.items():
            if field in locked:
                continue
            old_val = getattr(entity_dto, field, None)
            if old_val == new_val:
                continue
            changes.append((field, old_val, new_val))
        return changes
    ```
