<objective>
Land the structural prerequisite for BIBLE-01's "Bible persists to SQLite" claim by retiring the Phase-2 JSON ledger as a parallel persistence store. Build `trezarr/output/ledger_sqla.py` (the SQLAlchemy-backed LedgerSQLA with the same interface as Phase-2 Ledger), add `migrate_json_ledger_if_needed` to `trezarr/db/migration_runner.py` for the one-shot JSON→SQLite import (commit FIRST, rename SECOND per Pitfall 5), update the SIX `ledger.check`/`ledger.record` call sites in `trezarr/translate/engine.py` (lines 421, 438, 454, 479, 520, 537) to `await ledger.check`/`await ledger.record` (Option C from PATTERNS §Pattern 5 — locked as the planner decision), and wire the new startup sequence into `trezarr/cli.py` so the SQLA-backed Ledger is constructed from the start. Regression-test the Phase-2 ledger interface against the new backend by re-running the entire tests/output/test_ledger.py suite against LedgerSQLA via a duplicated tests/output/test_ledger_sqla.py.

Purpose: After this plan, the SQLite `processed_file` table is the single source of truth for idempotency tracking — no parallel JSON store, no dual-write debug mode. This is the cleanup phase that makes BIBLE-01's "persists to SQLite" claim unambiguously true. Per BIBLE-01, the substrate underneath the Series Bible itself must persist to SQLite; leaving an unawaited `ledger.record(...)` coroutine at line 454 (the read/batch-failure quarantine) would mean the in_progress→quarantined transition is silently dropped and the processed_file table is NOT the single source of truth. The existing Phase-1/2/3 `engine.py` translate logic continues to work UNCHANGED in semantics (data shape, status values, atomic write, quarantine flow) — only the storage backend changes.

Output: `trezarr run --once` constructs an `AsyncEngine` + `LedgerSQLA` at startup, migrates any pre-existing JSON ledger into SQLite once (idempotent on re-run), and the translate loop uses `await ledger.check(...)` / `await ledger.record(...)` against the SQLite-backed implementation. After the first run, `/config/processed_files.json` is renamed to `/config/processed_files.json.migrated.bak` and the SQLite `processed_file` table holds every recorded entry.
</objective>
