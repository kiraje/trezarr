# Phase 8 — UI Design Contract

> Visual and interaction contract for Phase 8: Editable Series Bible UI.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Scope:** The single human override valve. A Bible editor that lets an operator view, correct, and lock
> per-series Characters, Address Map, Term Dictionary, and Register. Extends the Phase-7 SPA verbatim —
> no new design system, no new color palette, no new type scale. Functional-first; correctness-bearing
> interactions take priority over visual polish.

## Component Inventory

All components are hand-rolled with Tailwind CSS. No new external libraries. The following are NEW components for Phase 8 (all Phase-7 components are reused verbatim).

### LockBadge

Props: `state: "locked" | "inference"`

Renders: `<span>` with 4px colored dot + state text label. Same structure as StatusBadge. Height 20px, 6px horizontal padding, 4px gap between dot and text, 12px regular text. Background and text from LockBadge semantic palette above.

Never render color-only. Screen reader reads "Locked" or "Inference".

Placement: inline to the right of the field value in every editable row. Always visible without interaction.

```
[anh]  [Locked •]   [🔓 Unlock]
[em]   [Inference •] [🔒 Lock]
```

### LockToggleButton

Props: `state: "locked" | "inference"; onToggle: () => void; disabled?: boolean`

Renders: icon-only button, 32px × 32px touch target.
- State `locked`: lucide `Unlock` icon, muted color, aria-label "Unlock this field". On click: clears lock.
- State `inference`: lucide `Lock` icon, muted color, aria-label "Lock this field". On click: sets lock.
- On hover: icon turns `text-accent`.
- Focus ring: `outline: 2px solid #3b82f6; outline-offset: 2px`.
- `disabled=true` (used when the hard-block condition is active): `opacity-50 cursor-not-allowed`.

### FieldHistoryPanel

A read-only slide-in panel (or inline expansion below the row) that renders the `bible_event` timeline for a field.

- Trigger: a `Clock` icon (lucide, 14px, muted) to the right of the LockBadge. On click: expands the panel below the row (not a modal).
- Panel dimensions: full-width card, secondary background, border-border, 16px padding, max-height 320px with overflow-y scroll.
- Each event is a row: timestamp (12px muted, `HH:MM:SS DD MMM`) + source badge (12px regular, same shape as StatusBadge but with values `inference` / `lock` / `import` / `system` in muted palette) + "old → new" values (12px regular, text-primary). Most-recent first.
- Empty state: "No history for this field." in 12px muted.
- Close: clicking the Clock icon again collapses the panel. No X button needed.

### PronounCombo

Props: `value: string; onChange: (v: string) => void; terms: string[]; placeholder?: string`

A combobox for selecting a Vietnamese pronoun term. Used in all `self_term` / `address_term` inputs in the Address-Map editor.

Behavior:
- Renders as a `<select>` with options from the `terms` prop (loaded from `GET /api/pronouns`) plus a `"custom…"` option at the bottom.
- When `"custom…"` is selected: the `<select>` is replaced inline with a `<input type="text">` pre-filled with the current value. The input has the same styling as Settings `TextField`. A "Done" text link (accent, 12px) to the right confirms the custom entry and trims whitespace.
- The current value, if not in `terms`, renders the `<input type="text">` directly (skipping the `<select>`) — i.e. already-custom values display as text inputs by default.
- Input styling: h-9 (36px), secondary background, border-border, 8px horizontal padding, 14px regular, focus ring.
- No free-text typing on the `<select>` — must pick from list or choose "custom…". This is the typo guard (D-86).

### ReciprocaldSuggestionPanel

Props: `forwardPair: AddressMapEntry; reciprocalSuggestion: AddressMapEntry | null; onConfirm: (reciprocal: AddressMapEntry) => void; onDismiss: () => void`

Appears inline below the Address-Map row editor when a user edits `self_term` or `address_term` of a directed pair.

Layout: a bordered inset card (border-border, 16px padding, secondary background) with the heading "Reciprocal pair (auto-suggested)" in 12px semibold, followed by:

- If `reciprocalSuggestion` is non-null: shows the reverse pair (e.g. "Mary → John: **em** / **anh**") with two PronounCombo inputs (pre-filled from suggestion, editable), a "Confirm reciprocal" button (accent, sm), and a "Skip — set manually later" text link (muted, 12px).
- If `reciprocalSuggestion` is null: shows "No known reciprocal for this pair. Set the reverse pair manually." in 12px muted text, with a "Dismiss" text link.

The panel auto-dismisses when the user navigates away from the row. It does not block saving the forward pair.

### BibleTabBar

A horizontal tab bar for switching between the four Bible sections.

Tabs: Characters | Address Map | Terms | Register

Renders: `<nav>` with four `<button>` elements in a horizontal flex row. Each tab:
- 14px regular, text-muted when inactive, text-primary when active.
- Active tab: 2px bottom border in accent color (`border-b-2 border-accent`), no background change.
- Inactive tab: `hover:text-text-primary`, no border.
- Tab height: 40px.
- Bottom border of entire tab bar: 1px border-border separating tabs from content.

No sliding ink or animation (functional-first).

**Purpose:** Entry point. Lists all series that have a Bible in the database.

**Layout:** Vertical stack. Page heading "Series Bible" (18px semibold) at top. Then a table.

**Table columns:**

| Column | Width | Content |
|--------|-------|---------|
| Series | 50% | Series title (text-primary, 14px); links to `/bible/:id` |
| Characters | 15% | Count (12px muted) |
| Terms | 15% | Count (12px muted) |
| Register | 20% | Register value string (12px, text-primary) or "—" if unset |

Table styling: same as Phase-7 JobTable — 40px rows, border-bottom on header, alternating bg-stripe, row hover `bg-[#22263a]`, `overflow-x-auto` wrapper.

Entire row is clickable (navigates to `/bible/:id`). Cursor: pointer.

Empty state: heading "No series in Bible" + body "Series Bibles are created automatically when Trezarr processes an episode. Run a translation to get started." (centered, 12px muted).

Error state: amber banner "Could not load series list. Check the server logs." (same amber palette as Phase-7 API-unreachable banner).

### BibleEditor Page (`/bible/:id`)

**Purpose:** Full Series Bible editor for one series. Four sections via BibleTabBar.

**Header:** Series title in 18px semibold + the register value as a small badge (12px muted) beside it, on the same line. A breadcrumb: `← Bible` (12px accent, links to `/bible`).

**BibleTabBar** below the header, above the section content.

**Register Section (smallest scope, specify first):**

A single `SectionCard` (identical to Phase-7 `SectionCard` — bg-surface, border-border, rounded, 24px padding):
- Heading "Register" (16px semibold).
- Helper text: "The register governs formality level across all translation passes. Locked register survives re-analysis." (12px muted).
- One `TextField` labeled "Register value" with the current value pre-filled (the `register` alias from the DTO — always use `response["register"]`). Standard input styling (36px, secondary background, border-border, 8px padding, 14px regular).
- LockBadge + LockToggleButton inline to the right.
- FieldHistoryPanel trigger (Clock icon) to the right of the LockToggleButton.
- "Unlock" affordance note (12px muted, only shown when NOT locked): "This value may be overwritten on the next episode analysis. Lock to pin it."
- Save button at bottom: "Save Register" (full-width, accent, 36px). Disabled when no unsaved changes.

**Characters Section:**

A `SectionCard` with heading "Characters" + an "Add Character" button (accent, sm, right-aligned in the heading row).

Characters table (same table primitives as Phase-7):

| Column | Width | Content |
|--------|-------|---------|
| Name | 22% | 14px text-primary; editable inline |
| Gender | 12% | "male" / "female" / "unknown" dropdown (12px regular) |
| Age | 10% | Number or "—"; editable inline |
| Role | 28% | Text field (14px) |
| Lock | 14% | LockBadge per row (locks all fields together per character) |
| History | 7% | Clock icon trigger |
| Actions | 7% | Edit icon only (no delete — D-83) |

Row editing: clicking the edit icon (lucide `Pencil`, 14px, muted) puts the entire row into edit mode — fields become inputs in-place. "Save" and "Cancel" appear as text links (accent / muted, 12px) to the right of the row.

Lock scope for Characters: the Lock toggle applies to the entire character row (all fields). The LockBadge shows "Locked" if ANY field is in `locked_fields`; shows "Inference" if none are locked. (Simplification for v1 — per-field locking within a character is over-engineered for the operator UX; the whole-character lock is sufficient and matches the "lock the character identity" mental model.)

**Add Character flow:** Clicking "Add Character" opens an inline form row at the top of the table (above existing characters). Same fields as the edit row. "Add" button (accent, sm) + "Cancel" text link. On success: row appears in the table; toast "Character added." On error: toast "Failed to add character."

No character delete affordance appears in the UI (D-83).

**Address Map Section:**

A `SectionCard` with heading "Address Map" + "Add Pair" button (accent, sm, right-aligned).

Address Map table:

| Column | Width | Content |
|--------|-------|---------|
| Speaker | 18% | Character name (14px text-primary); dropdown picker on edit |
| Addressee | 18% | Character name (14px text-primary); dropdown picker on edit |
| Self term | 12% | PronounCombo (view: text-primary; edit: PronounCombo) |
| Address term | 12% | PronounCombo (view: text-primary; edit: PronounCombo) |
| Lock | 10% | LockBadge |
| Relationship events | 10% | Count badge ("2 events") — read-only, opens event list on click |
| Valid from | 10% | Episode key or "—" (12px muted) |
| History | 5% | Clock icon |
| Actions | 5% | Edit icon; Delete icon (lucide `Trash2`, destructive color, only shown for unlocked pairs) |

Row editing: edit icon puts row into edit mode. Speaker and Addressee become `<select>` dropdowns populated from the characters list (not free-text — D-83 FK constraint). Self term and Address term become PronounCombo inputs. On edit, the ReciprocaldSuggestionPanel auto-renders below the row.

**Lock behavior for Address-Map rows:**
- Lock toggle is separate from the Save button. Clicking the LockToggleButton while in edit mode: if either `self_term` or `address_term` is empty/whitespace, the hard-block error appears inline below the lock button: "Both terms must be non-empty before locking a pair." The lock toggle stays disabled (`opacity-50 cursor-not-allowed`) until both terms are filled (D-87).
- Saving (without locking) is always allowed regardless of term values.
- If a pair is locked and in edit mode: the LockToggleButton shows the Unlock icon. Unlocking requires no confirmation (it loosens the pin; does not delete data).

**Relationship event read-only display:** Clicking the event count badge opens an inline expansion (similar to FieldHistoryPanel) showing the list of `RelationshipEvent` rows for this pair: episode marker + description. 12px muted. Read-only — no edit controls (D-88).

**"Lock to pin" affordance:** When a pair is UNLOCKED and in edit mode, show a callout banner above the pair form (not a warning — just a blue-tinted info strip using the Running badge background `#1e3a5f`, text `#60a5fa`): "This pair is not locked. An upcoming analysis pass may update these terms. Lock to pin your edit permanently."

**Add Pair flow:** "Add Pair" button opens an inline form at the top of the table. Speaker and Addressee are `<select>` dropdowns (character pickers). Self term and Address term are PronounCombo inputs. ReciprocaldSuggestionPanel appears as soon as both terms are filled. "Add" (accent) + "Cancel" text link. HTTP 422 on empty terms: inline error below the button. Toast on success/failure.

**Delete pair:** Trash2 icon, destructive color (`text-[#f87171]`), appears only on unlocked pairs (locked pairs show no delete affordance). On click: inline confirmation replaces the icon row: "Delete this pair? [Delete] [Cancel]". Delete button uses destructive background. On confirm: row disappears, toast "Pair deleted."

**Term Dictionary Section:**

A `SectionCard` with heading "Term Dictionary" + "Add Term" button (accent, sm, right-aligned).

Terms table:

| Column | Width | Content |
|--------|-------|---------|
| Source term | 25% | 14px text-primary; case-sensitive (note below) |
| Vietnamese rendering | 30% | 14px text-primary |
| Category | 15% | Pill badge: "proper noun" / "title" / "place" / "jargon" (12px muted, no color differentiation — text-only categories) |
| Lock | 12% | LockBadge |
| History | 8% | Clock icon |
| Actions | 10% | Edit icon + Delete icon (trash) |

Row editing: same inline edit-mode pattern as Characters. Category becomes a `<select>` with the four options. Lock toggle is per-row (all fields of one term together).

Add Term: inline form at top of table. Source term is a text input. Vietnamese rendering is a text input. Category is a `<select>`. "Add" + "Cancel". On HTTP 422: inline error.

## Interaction & State Contracts

### Data loading

- `BibleList` page: `GET /api/series` on mount (no polling — static data). Show skeleton on load; amber banner on error.
- `BibleEditor` page: `GET /api/series/{id}/bible` on mount. Show skeleton on load; amber banner on error. No polling — Bible data does not auto-update between user edits.
- `GET /api/pronouns`: fetched once on `BibleEditor` mount, cached in component state for the lifetime of the page. Used by all PronounCombo instances.

### Edit lifecycle

1. User clicks the Edit icon on a row → row enters edit mode in-place (inputs appear). All other rows remain read-only.
2. Only one row can be in edit mode at a time per section. Clicking Edit on a second row while the first is dirty: show inline prompt "You have unsaved changes. Discard and edit this row? [Yes] [Cancel]" (no toast — inline text link pattern, same muted-amber inline callout as warning stripe but smaller).
3. User modifies values → dirty state tracked locally. Save/Cancel text links are visible.
4. User clicks Save: `PATCH /api/series/{id}/characters/{cid}` (or equivalent endpoint per entity type). On success: row exits edit mode, LockBadge updates from API response. Toast "Changes saved." On error: toast "Failed to save changes. Check the server logs." Row stays in edit mode.
5. User clicks Cancel: row exits edit mode, all changes discarded. No confirmation (changes are not persisted; Cancel is safe).

### Lock toggle lifecycle

- LockToggleButton is available in BOTH view mode and edit mode.
- In view mode (no edit): clicking Lock → sends `PATCH` with current stored value + `lock: true`. On success: LockBadge updates to "Locked". Toast "Field locked."
- In view mode: clicking Unlock → sends `PATCH` with current stored value + `lock: false`. On success: LockBadge updates to "Inference". Toast "Field unlocked."
- In edit mode (Address-Map only): the hard-block check runs client-side before the lock request. If either term is empty, the LockToggleButton is `disabled`. The error message "Both terms must be non-empty before locking a pair." appears inline below the lock button. The Save button (without locking) remains enabled.

### Reciprocal suggestion trigger

- Fires client-side when BOTH `self_term` and `address_term` have been modified in an Address-Map edit row.
- Look up `kinship_reciprocal[`${self_term}|${address_term}`]` from the `/api/pronouns` response.
- If found: ReciprocaldSuggestionPanel opens below the row with pre-filled suggestion.
- If not found: ReciprocaldSuggestionPanel opens with the "no known reciprocal" message.
- Panel is dismissed by clicking "Confirm reciprocal", "Skip — set manually later", or "Dismiss".
- Confirming reciprocal: on Save of the forward pair, the client sends TWO PATCH requests — one for the forward pair, one for the reverse. If the reverse pair does not yet exist, the client sends a POST to create it. If either fails: toast "Pair saved, but reverse pair update failed. Set it manually." (no rollback — forward pair is the user's primary intent).

### Warn-but-allow validation (D-87)

Non-blocking warnings appear as amber banner strips above the Save button within the row edit form. They do not prevent saving or locking. They render at 12px in the amber palette (`#fbbf24` text on `#451a03` background, 8px padding, rounded, 4px gap between icon and text).

Warning conditions (evaluated client-side on every field change):
1. **Reciprocal incoherence:** entered pair contradicts the existing reverse row. Message: "The reverse pair (Addressee → Speaker) exists with different terms. Confirm both directions are intentional."
2. **Pair not in kinship table:** `kinship_reciprocal` has no entry for this pair. Message: "No known reciprocal will be auto-inferred for this pronoun pair."
3. **Intimate term, low confidence:** `self_term` or `address_term` is in `["anh", "em", "tao", "mày"]` AND the pair was inferred (LockBadge was "Inference" before editing). Message: "This is an intimate pronoun pair. The analyzer was not confident about this relationship — confirm before locking."
4. **Gender mismatch:** `address_term` is gender-marked (e.g. `anh` = male address, `chị` = female address) and the addressee character's `gender` field contradicts it. Message: "Address term '{term}' is typically used for a {implied_gender} speaker, but '{addressee_name}' is recorded as {character_gender}."

At most one warning banner per condition is shown. Multiple conditions can show simultaneously (stacked, each with its own strip, 4px gap between strips).

### API error handling

- Network error or 5xx on any Bible API call: amber banner at top of page content (same as Phase-7 API-unreachable pattern). Does not dismiss automatically — requires a page refresh or a new successful request.
- HTTP 422 on lock attempt with empty terms: handled by the hard-block inline error, not the banner.
- HTTP 404 for a series Bible: redirect to `/bible` with toast "Series not found."

### Polling

No polling on the Bible editor. Data is loaded on mount and on each successful save/lock action (the row's DTO is updated from the API response). The `GET /api/pronouns` endpoint is fetched once per page load.

### Navigation

New routes added to `App.tsx`:
- `/bible` → `BibleList` page (replaces the Phase-7 placeholder `<div>`)
- `/bible/:id` → `BibleEditor` page (default tab: Characters)

The AppShell "Bible" NavItem: remove `disabled={true}`, activate as a real NavLink to `/bible`. The `BookOpen` icon is already correct.

## Implementation Notes for Executor

1. **Extend, do not replace.** `App.tsx`, `AppShell.tsx`, `api/client.ts` are all modified (routes added, Bible NavItem un-disabled, API wrappers added). Every other Phase-7 component is reused verbatim — no changes to `StatusBadge`, `Toast`, `MaskedSecretInput`, `JobTable`, `LogViewer`, or `RetryButton`.

2. **Token discipline.** Use only the semantic Tailwind tokens from `tailwind.config.js` (`bg-bg-base`, `bg-bg-surface`, `bg-bg-stripe`, `border-border`, `text-text-primary`, `text-text-muted`, `bg-accent`, `text-accent`, `text-destructive`). Do not introduce new color hex values in component code. The LockBadge color values match `StatusBadge`'s `done` (locked = green) and `queued` (inference = slate) entries — reuse those hex values directly from the StatusBadge palette.

3. **Register alias.** The API returns `"register"` (not `"register_value"`) per CR-02. Read `response.register`. If implementing a TypeScript interface for `SeriesBibleDTO`, name the field `register: string | null` — not `register_value`.

4. **PronounCombo is NOT a free-text input by default.** It is a `<select>` first, with free-text only after the user explicitly chooses "custom…". This is the core typo-prevention mechanism (D-86). Do not simplify it to a plain `<input type="text">`.

5. **Hard-block on lock with empty term is client-side only.** The server also returns HTTP 422. But the client must disable the LockToggleButton and show the error message WITHOUT waiting for the server — immediate feedback on the local field values (D-87).

6. **Two PATCH calls for reciprocal confirm.** When a user confirms a reciprocal suggestion, save both pairs. If only the forward pair is being locked and the user chose "Skip" for the reciprocal, send only one PATCH. Never silently write the reverse pair without explicit user confirmation (D-85).

7. **No inline row editing for Register.** Register is a single card form (not a table row), so its edit pattern is the Settings-page pattern: field + Save button. No Edit icon needed.

8. **Character edit is per-field lock conceptually, but the LockToggleButton applies to all character fields together.** Implementing per-field character locking (separate lock toggles for name, gender, age, role) is over-engineered for v1. The LockBadge shows "Locked" if `locked_fields` is non-empty, "Inference" if empty. The LockToggleButton sends `lock: true` for all editable character fields together.

9. **FieldHistoryPanel is inline expansion, not a modal.** It renders as a card below the triggering row. The table does not scroll past it — the expansion pushes content down. Do not use `position: absolute` or a portal.

10. **BibleTabBar uses `<button>` elements, not `<a>` elements.** Tab switching is client-side state (`useState<Tab>`), not routing. The URL does not change when switching tabs within a series Bible.
