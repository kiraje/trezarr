    DRAWING_RE = re.compile(r'\{\\p[1-9]\d*\}')

    Format: line dynamic parsing (per RESEARCH §Open Question 1 — dynamic is safer): when processing the [Events] section, read the Format: line and build a column-index map {field_name: index}. The Text field index is always the last column. If the Format: line is absent or unparseable, fall back to the standard 10-field layout (Text at index 9, split on first 9 commas). This handles both ASS (Layer field) and SSA (Marked field) variants transparently, and also handles any non-standard field ordering.

    read_ass(path) algorithm (per RESEARCH §3.3):
    1. read_bytes → detect_encoding → decode with errors="replace"
    2. Detect line ending: le = "\r\n" if "\r\n" in text else "\n"
    3. Split text on section header pattern (a line starting with "[" at position 0) to isolate sections. Preserve the header lines as part of the section content. Each non-[Events] section → AssOpaqueSegment.
    4. For the [Events] section:
       a. Read the Format: line → build column index map. Text is the last column. Compute text_comma_idx = (number of fields before Text) - 1 as the maxsplit value for split(",", text_comma_idx). Standard ASS = split(",", 9).
       b. For each subsequent line in [Events]:
          - If starts with "Comment:" → AssOpaqueSegment (verbatim, including line ending)
          - If starts with "Dialogue:": strip "Dialogue: " prefix then split on "," with maxsplit=text_comma_idx. If len(parts) < text_comma_idx+1: malformed → UserWarning + SubLine(raw=line, ...) + AssOpaqueSegment for the slot (or mark as opaque; choose one consistently). Otherwise: extract start_tc = parts[1].strip(), end_tc = parts[2].strip(), text = parts[text_comma_idx] (no strip), prefix = "Dialogue: " + ",".join(parts[:text_comma_idx]) + ",". Detect karaoke/drawing: if KARAOKE_RE or DRAWING_RE found in text, set SubLine(index="", start_tc=start_tc, end_tc=end_tc, text=text, raw=text). Otherwise SubLine(index="", start_tc=start_tc, end_tc=end_tc, text=text, raw=None). Append AssDialogueSlot(prefix=prefix, line_ending=le, sub_index=len(sub_lines)) and sub_lines.append(sl).
          - Blank line or unrecognized line → AssOpaqueSegment
    5. Construct AssDoc(segments=segments, encoding=encoding, line_ending=le)
    6. Return SubDoc(lines=sub_lines, encoding=encoding, line_ending=le, separators=[], leading="", trailer="", envelope=ass_doc)

    write_ass(doc, path) algorithm (per RESEARCH §3.4 and PATTERNS.md §"write_ass pattern"):
    1. ass_doc: AssDoc = doc.envelope
    2. Iterate segments: AssOpaqueSegment → emit raw verbatim; AssDialogueSlot → emit slot.prefix + (sl.raw if sl.raw is not None else sl.text) + slot.line_ending
    3. result = "".join(parts); Path(path).write_bytes(result.encode(ass_doc.encoding))

    Important constraints:
    - SubLine.index is always "" for ASS cues (ASS has no numeric line indices — RESEARCH A2)
    - Never call pysubs2 on the write path (D-91)
    - The pipeline-agnostic contract: SubDoc.separators = [] for ASS (no inter-cue blank lines; the ASS file's inter-section structure is captured in AssOpaqueSegment, not in separators)
    - Karaoke/drawing: BOTH text AND raw set to original Text per RESEARCH A7 (satisfies check 2 non-empty + check 3 raw-is-not-None skip)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ASS file bytes → read_ass | Untrusted bytes from disk (subtitle files from user media library) |
| Dialogue Text field → karaoke/drawing detection | Text content from parsed ASS files; matched against KARAOKE_RE/DRAWING_RE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03-A | Denial of Service | KARAOKE_RE: `\{\\k[foi]?\d+\}` | mitigate | Pattern uses fixed-width braces and no nested quantifiers; applied per-line after section split. Max line length in a subtitle file is practical hundreds of chars. Safe per ASVS L1 V5. |
| T-09-03-B | Denial of Service | DRAWING_RE: `\{\\p[1-9]\d*\}` | mitigate | Fixed-prefix match with `[1-9]\d*` (non-nested). Same safe context as above. |
| T-09-03-C | Denial of Service | SENTINEL_ONLY_RE: `^(<<T\d+>>\s*)*$` | mitigate | Pattern is anchored (^ and $) and applied to short per-line strings (sentinel tokens are bounded in count per cue). No catastrophic backtracking path. |
| T-09-03-D | Tampering | ASS Effect field | accept | Effect field is index 8 in the 10-field layout; it is captured inside the AssDialogueSlot.prefix string and emitted verbatim. Trezarr never executes effect strings — they are only displayed by the player renderer. No injection risk for Trezarr itself. |
| T-09-03-E | Tampering | ASS drawing commands | mitigate | Drawing runs are set as SubLine.raw and never sent to the LLM (DRAWING_RE gate). The coordinates are byte-identical on write-back. No geometry is interpreted or executed by Trezarr. |
| T-09-03-F | Information Disclosure | Path traversal via sidecar | accept | Not applicable here — ass.py is a pure codec with no path-writing; write_ass receives an already-resolved path from the caller (write_vi_sidecar in output/write.py which holds the path-traversal guard). |
</threat_model>
