<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Subtitle cue text → attribution prompt | Source cue text included in the attribution prompt; a crafted cue attempts to manipulate speaker attribution output |
| LLM attribution output → name matching | LLM-produced speaker/addressee names are matched against known characters before acceptance |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Tampering | Prompt injection via subtitle cue in attribution prompt | mitigate | Cue texts appear under the numbered [LINES TO ATTRIBUTE] section as data, labeled with index numbers. The attribution instruction is in the system/user preamble. The sentinel/numbered-line protocol (D-12/D-13) is not applied in Pass 2 (attribution does not parse numbered output into cues) — but the structural labeling provides the same data-vs-instruction separation. Unrecognizable attribution output falls back to LOW confidence. |
| T-05-05-02 | Spoofing | LLM returns attribution with fabricated character names (not in bible.characters) to force wrong pronoun pair selection | mitigate | Name-matching post-processing: any speaker/addressee name not in bible.characters is set to None → LOW confidence → safe default. This is the test_unmatched_name_safe_default assertion. |
| T-05-05-03 | Tampering | BatchAttribution JSON with extra/unexpected fields | mitigate | Pydantic model_validate_json ignores extra fields by default. Only expected fields (line_index, speaker, addressee, confidence) are used. |
| T-05-05-SC | Tampering | npm/pip/cargo installs | accept | No new packages. Residual risk: LOW. |

Residual risk after mitigations: LOW. The name-matching gate is the primary security control; it converts LLM inference into a safe-by-default result when output is unrecognized.
</threat_model>
